---
title: "项目结构"
description: "从一个 agent 起步，应用代码放在它旁边；只有当需要可独立寻址的多个 agent 时，才拆分为工作区。"
---

从一个位于 `agent/` 的根 agent 开始。根 agent 通过自己的 HTTP API 或频道接收请求；它可以拥有任意数量的工具、技能和子 agent。浏览器应用文件放在 `agent/` 之外。

| 当你需要…                            | 结构                                        |
| ------------------------------------ | ------------------------------------------- |
| 一个 agent，带或不带浏览器应用       | `agent/` 位于应用代码旁边                   |
| 某个 agent 委派出去的专家角色        | 该 agent 内部的 `agent/subagents/<name>/`   |
| 多个可独立寻址、共享包与部署的 agent | eve agent 工作区中的 `agents/<name>/agent/` |
| 独立的依赖、版本或发布节奏           | 独立的 agent 包或项目                       |

每个根 agent 都可以拥有[声明的子 agent](/docs/subagents#declared-subagents)，它们有自己的提示词、工具和沙箱。这些专家角色没有独立的频道端点，也不继承父级编写的能力。如果只是需要一个可选的过程（procedure），改用[技能（skill）](/docs/skills)即可。

## 单个 agent

独立 agent，或 Web 应用内的 agent，使用这种布局：

```text
project/
├── package.json
├── agent/
│   ├── instructions.md
│   ├── tools/
│   └── subagents/
├── evals/
├── app/                    # 可选的 Next.js 浏览器应用
└── next.config.ts          # 可选的 Next.js 集成
```

按照[入门指南](/docs/getting-started)创建 agent。[Agent 文件参考](/docs/reference/agent-files)列出了受支持的路径。agent 专用的辅助代码放在 `agent/lib/`；可复用的能力通过[扩展（extension）](/docs/extensions)共享。

要生成聊天 UI，在项目根目录运行 `eve add channel/web`，然后选择 Next.js 或 TanStack Start。已有的浏览器应用请遵循对应的[框架集成指南](/docs/guides/frontend/overview#per-framework-integration)。

## 多个根 agent

例如，当客户端需要分别寻址"支持"和"研究"两类能力时，使用 eve agent 工作区：

```text
project/
├── package.json
├── agents/
│   ├── support/
│   │   ├── agent/
│   │   └── evals/
│   └── research/
│       ├── agent/
│       └── evals/
└── apps/                   # 可选的同级应用，不是 eve 工作区成员
    └── web/
```

各成员共享根 package、依赖、脚本和 Vercel 部署；目录名就是它们在 CLI 和公开路由中的标识。成员没有自己的 `package.json`：一旦添加，该目录就会被排除出 eve 工作区发现。与包管理器的工作区不同，这种布局不会给成员划分独立的依赖或版本边界。

先创建工作区，再选择一个 agent 运行：

```bash
npx eve@latest init operations --agents support,research
cd operations
npx eve dev --agent support
```

既可以在 `agents/<name>/` 下运行 `dev`、`info`、`eval` 等 agent 命令，也可以在工作区根目录传 `--agent <name>`。`eve dev --agent support` 只运行选中的 agent，不运行同级应用。需要时另行启动其他 agent；本地[工作区同级调用](/docs/subagents#vercel-workspace-peers)需要显式 transport。

在 Vercel 上，从根目录运行 `eve link` 和 `eve deploy`；部署会包含所有成员，且不要求有前端。自托管请[分别构建并运行每个成员](/docs/guides/deployment/self-hosting#run-workspace-members)。

## 独立发布

当多个 agent 需要独立的依赖或发布节奏时——即使在同一个 monorepo 里——使用独立的包或项目。它们不是 eve agent 工作区成员。通过[工作区扩展](/docs/extensions#use-an-extension-in-a-workspace)共享能力；跨部署的委派使用[远程 agent](/docs/guides/remote-agents)。

## 配置 Web 部署

前端和 agent 如何一起运行，与你有多少个 agent 无关，按需选择：

- **把 agent 加进 Next.js 应用：** 在 `next.config.ts` 中使用 [`eve/next`](/docs/guides/frontend/nextjs)。Next.js 拥有应用生命周期；该集成会在本地启动 agent 进程并代理请求，在 Vercel 上则贡献独立的 agent 服务。根 Next.js 应用既可以紧邻 `agent/`，也可以紧邻 `agents/`；工作区成员会被自动发现。`apps/web/` 这类同级应用可以通过 `eveRoot: "../.."` 选择自己的 eve 项目。
- **给 agent 工作区加前端：** 把前端作为同级应用，例如放在 `apps/web/` 下。在 Vercel 上，在[根 `vercel.ts` 中使用 `eve/vercel`](/docs/guides/deployment/vercel#compose-agents-with-other-vercel-services) 把 agent 与前端服务一起贡献出来。[自托管](/docs/guides/deployment/self-hosting#run-workspace-members)时，用你自己的进程管理器运行这些服务并配置反向代理。前端不需要 `eve/next`。

`apps/web/` 是一种组织约定，不是 eve 的文件系统槽位。部署配置拥有同级服务；eve 只发现 agent。两个 Vercel 集成都会把服务部署在一起，而不是各自独立发布。

在独立 agent 上运行 `eve add channel/web`，或用 `--agent <name>` 选择工作区中的某个 agent。安装器会询问使用哪个框架，并在 `apps/web/` 下创建 Next.js 或 TanStack Start 前端。选择 **Vercel services** 会配置独立的 Vercel 服务并用 `pnpm dev:all` 运行；本地运行它们不需要 link Vercel 项目。选择 **Next.js** 或 **TanStack Start** 则由前端承载 agent，用 `pnpm dev:web` 运行应用。只想要一个 agent 加 eve 终端 UI 时，使用 `pnpm dev` 或 `pnpm dev:eve`。

## 添加第二个根 agent

把单 agent 项目改造成工作区：把原有的 agent 从项目根移走：

```bash
mkdir -p agents/support
mv agent agents/support/agent
```

如果存在 `evals/` 目录，把它移到 `agents/support/evals/`。`package.json`、依赖、环境文件以及任何浏览器应用都留在项目根。**不要**留下根级 `agent/` 目录：即使 `agents/` 同时存在，eve 也会把含有 `agent/` 的项目当作单 agent 项目。

添加下一个 agent 之前：

- 更新 `tsconfig.json` 以包含 `agents/**/*.ts`，并保留原有的应用 include。更新被移动文件的导入路径和路径别名，包括脚手架生成的、指向 `./agent/*` 或 `./evals/*` 的 `package.json#imports` 条目。
- 更新那些假设只有一个 agent 的脚本。agent 范围的命令使用 `--agent support`；用根目录 `eve build` 构建纯 agent 的 Vercel 工作区。Next.js 应用保留框架脚本并遵循其[构建说明](/docs/guides/frontend/nextjs#dev-vs-deploy-topology)。
- 为具名 agent 的公开路由更新 HTTP 客户端和 webhook 注册。在根 Next.js 应用中，删除单 agent 使用的 `eveRoot` 覆盖以启用工作区发现，并在客户端 hook 中选择 `support`。把 agent 名与 durable-session 链接一起存储。

然后添加第二个 agent 并检查发现结果：

```bash
npx eve init research
npx eve info --agent support
npx eve info --agent research
```

用 `npx eve eval --agent support` 运行被移动 agent 的 evals。之后从工作区根目录用 `npx eve init <name>` 添加更多 agent。
