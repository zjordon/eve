# eve - 使用指南

> 生成时间: 2026-10-17
> 分析对象: D:\dev\git\z_jordon\fork\eve（vercel/eve 的 fork，主包 eve@0.80.1，基于 main 分支 c8332e1f）

eve 是 Vercel 推出的**文件系统优先（filesystem-first）的持久化后端 AI Agent 框架**（目前为 beta）。
你把一个 Agent 写成磁盘上的一个目录——指令、技能、工具、连接、频道、子 Agent、定时任务全部是文件——eve 负责编译并运行它。

## 1. 快速开始

### 1.1 环境要求

| 要求 | 版本 | 说明 |
|------|------|------|
| Node.js | >= 24 | 仓库 `.nvmrc` 锁定 `24`（`nvm use` / `fnm use`） |
| 包管理器 | pnpm | 仅开发本仓库需要；终端用户用 npx 即可。版本由根 `package.json` 的 `packageManager: pnpm@12.7.0` 锁定（`corepack enable` 自动处理） |
| 操作系统 | macOS / Linux / Windows | CLI 为 Node 程序；部分沙箱能力（Docker、microsandbox）依赖 Linux 容器 |
| 凭据 | 三选一 | ChatGPT 订阅（/login OAuth）、Vercel 账号 / AI Gateway、或 OpenAI / Anthropic API Key |

### 1.2 安装（终端用户）

```bash
# 创建新 Agent：建目录、装依赖、初始化 Git、启动交互式 TUI
npx eve@latest init my-agent

# 指定模型（AI Gateway 模型 ID）
npx eve@latest init my-agent --model openai/gpt-5.6-terra
# 显式指定推理力度
npx eve@latest init my-agent --model openai/gpt-5.6-terra --reasoning high

# 在已有项目中加入 eve（生成 agent/ 目录并添加 eve、ai、zod 依赖）
cd myapp
npx eve@latest init .
```

默认生成的 Agent 使用 `openai/gpt-6-luna-fast`（reasoning: high）。

### 1.3 快速运行

```bash
cd my-agent
npm run dev        # 启动开发模式：TUI 界面 + Agent 文件热重载
```

本地开发**无需浏览器登录、无需 Vercel 项目**：在 TUI 里 `/login` 选择凭据来源即可（ChatGPT 订阅 / Vercel 账号 / API Key）。

> [!NOTE]
> `eve` npm 包内含全部文档，编码类 Agent 可直接读 `node_modules/eve/docs`（这是 eve "Docs is priority #1" 原则的落地）。

### 1.4 最小可运行示例

一个 Agent 只需要 `agent/instructions.md`（必填的系统提示词）。其余全部可选：

```text
my-agent/
└── agent/
    ├── agent.ts            # 可选：模型与运行时配置（defineAgent）
    ├── instructions.md     # 必填：常驻系统提示词
    ├── tools/              # 可选：模型可调用的类型化函数
    │   └── get_weather.ts
    ├── skills/             # 可选：按需加载的过程性知识（markdown）
    ├── connections/        # 可选：外部服务连接（MCP / OpenAPI）
    ├── channels/           # 可选：消息频道（Slack、Discord、Web…）
    ├── subagents/          # 可选：专家子 Agent
    ├── schedules/          # 可选：cron 定时任务
    └── memory/             # 可选：长期记忆槽位
```

`agent/agent.ts`（选模型时才需要）：

```ts
import { defineAgent } from "eve";

export default defineAgent({
  model: "openai/gpt-6-luna-fast",
  reasoning: "high",
});
```

`agent/tools/get_weather.ts`：

```ts
import { defineTool } from "eve/tools";
import { z } from "zod";

export default defineTool({
  description: "Return mock weather data for a city.",
  inputSchema: z.object({ city: z.string().min(1) }),
  async execute({ city }) {
    return { city, condition: "Sunny", temperatureF: 72 };
  },
});
```

命名约定：**标识符由文件路径派生**——`agent/tools/get_weather.ts` → 工具名 `get_weather`；`agent/connections/linear.ts` → 连接名 `linear`。定义里不要再写冗余的 `name` 字段。

## 2. 配置说明

### 2.1 模型配置（agent.ts）

| 配置项 | 类型 | 说明 |
|--------|------|------|
| `model` | 字符串或 LanguageModel | 字符串走 Vercel AI Gateway（`provider/model-id`，如 `anthropic/claude-opus-5.5`）；对象则接受任意 AI SDK Provider 的 LanguageModel |
| `reasoning` | `high / medium / …` | 推理力度；省略时用 provider 默认值 |

三种直连 provider 助手（免 Gateway）：

| 助手 | 导入 | 默认模型 | 凭据 |
|------|------|----------|------|
| `openai()` | `eve/models/openai` | gpt-6-luna-fast | `OPENAI_API_KEY` |
| `anthropic()` | `eve/models/anthropic` | claude-sonnet-5 | `ANTHROPIC_API_KEY` |
| `chatgpt()` | `eve/models/openai`（experimental） | 走 ChatGPT 订阅 OAuth（/login），不可部署 | 本地凭据存储 |

其他 provider（Ollama / vLLM / Bedrock 等）：安装对应 AI SDK provider 包（如 `@ai-sdk/openai-compatible`）并传入其 LanguageModel（记得设置 `modelContextWindowTokens`）。

运行时换模型（三者写的是同一处源码）：

```bash
eve set model <id> [--reasoning high]   # CLI
# 或 TUI 内： /model <id>
```

### 2.2 环境变量

| 变量 | 必需 | 说明 |
|------|------|------|
| `OPENAI_API_KEY` | 二选一 | 直连 OpenAI |
| `ANTHROPIC_API_KEY` | 二选一 | 直连 Anthropic |
| `AI_GATEWAY_API_KEY` | 用 Gateway 字符串模型时 | Vercel AI Gateway；部署在 Vercel 上时可用项目 OIDC 替代 |
| `PORT` | 自托管时 | `eve start` 监听端口 |
| `EVE_CHAT_PASSWORD` | chat 模板 starter 模式 | Web Chat 模板密码 |
| `EVE_VOICE_PASSWORD` | voice 模板 | 语音模板密码 |

本地开发可用 `/login` 保存的凭据；**部署后必须把 API Key 放进服务端环境变量**。

### 2.3 仓库级配置（贡献者）

| 文件 | 作用 |
|------|------|
| `package.json` / `pnpm-workspace.yaml` | pnpm workspace（`apps/*`、`apps/fixtures/*`、`apps/frameworks/*`、`e2e/fixtures/*`、`packages/*`），依赖版本走 `catalog:` |
| `turbo.json` | Turborepo 任务编排 |
| `.nvmrc` | Node 24 |
| `pnpm-workspace.yaml` 的 `allowBuilds` | 白名单式放行安装期脚本（供应链防护） |

## 3. 主要功能

### 3.1 工具（tools）与人在环路审批

`agent/tools/<name>.ts` 用 `defineTool` 定义（zod 入参 schema）。支持 human-in-the-loop：工具可要求人工批准后才执行；批准卡片出现在 TUI 和各 button 型频道里。

### 3.2 技能（skills）

`agent/skills/*.md` 或 `SKILL.md` 目录，通过内置 `eve__skill` 工具渐进披露（progressive disclosure），支持 `deferred: true` 前置元数据按需加载。

### 3.3 连接（connections）

`agent/connections/<name>.ts`：

- `defineMcpClientConnection` — MCP 服务器客户端
- `defineOpenAPIConnection` — OpenAPI 服务

凭据经 `getToken` 注入（通常读 `process.env`），**模型永远看不到 URL 与凭据**；远端工具以内置 `eve__search` / `eve__tool` 之后的 `<connection>__<tool>` 形式暴露。动态连接用 `defineDynamic` 在 `session.started` / `turn.started` 时解析。安装现成集成：`eve add connection/linear`（registry 见 `apps/docs/registry/`）。

### 3.4 频道（channels）

内置频道（`docs/channels/`）：Web Chat（`channel/web`，Sign in with Vercel）、Slack、Discord、GitHub、Linear、Microsoft Teams、Telegram、Twilio（SMS/语音）、iMessage（Linq / Photon）、MCP channel（把 Agent 本身发布为 MCP 服务器）、自定义频道。

```bash
npx eve link                 # 关联 Vercel 项目
npx eve add channel/web      # 添加 Web Chat（选托管布局 + Vercel 登录鉴权）
npx eve deploy               # 发布
```

### 3.5 子 Agent（subagents）与任务

- 内置根 Agent 专用 `agent` 工具（共享沙箱的"root 副本"）
- 专家子 Agent：`agent/subagents/<name>/agent.ts`（各自的 `defineAgent`，`description` 必填）
- 远程子 Agent：`defineRemoteAgent`
- 子 Agent 调用作为**持久化任务（durable tasks）**运行

### 3.6 定时任务（schedules）

`agent/schedules/*.ts` 用 `defineSchedule({ cron, run })`（或带 cron frontmatter 的 markdown）。部署到 Vercel 时自动映射为 Vercel Cron Jobs（UTC）。注意：`eve dev` 永不触发 cron，`eve start` 会触发。

### 3.7 记忆（memory）

`agent/memory/<name>.ts` 用 `defineMemory({ description, scope, provider })`；内置 `fileMemory()` 文件存储 provider，可自定义 provider。保存需审批（approved saves）。

### 3.8 扩展（extensions）

npm 挂载的能力包（`agent/extensions/`），如 `eve/extensions/code`（CLI 编码工作流，源码在 `packages/eve-code`）、`eve/extensions/git`（GitHub PR 工作流，源码在 `packages/eve-git`）、`eve/computer-use`（Linux 沙箱桌面 computer-use，源码在 `packages/eve-computer-use`）。仓库还含 `packages/tracing`（`@vercel/agent-runs`，框架无关的 OTel 追踪 + 持久化 checkpoint）与 `packages/eve-self-modification`（自修改兼容入口），均为上游 monorepo 自带包。

### 3.9 评测（eve eval）

```bash
eve eval [ids...] --strict --junit .eve/junit.xml    # CI 推荐
eve eval --list / --tag / --exclude-tag / --verbose / --json
```

- 位置：应用根的 `evals/` 目录（与 `agent/` 平级），文件路径即 eval id
- 每个仓库恰好一个 `evals/evals.config.ts`（`defineEvalConfig`：judge 模型默认 `typesafe-ai/jev`、reporter、并发、超时、setup/teardown）
- 断言面：`t.send` / `t.succeeded` / `t.calledTool` / `t.check` / `t.judge`（LLM-as-judge）/ `t.loadedSkill`；支持 `cases` 数据集扇出与 `mockModel` 确定性运行（无需 provider 凭据）
- 产物落在 `.eve/evals/<timestamp>/`

## 4. API 接口

### 4.1 HTTP（默认 eve 频道）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/eve/v1/health` | GET | 健康检查（部署后验证用） |
| `/eve/v1/*` | — | 消息、流式响应、continuation、output-schema（客户端协议见 `docs/protocols/` 与 `docs/guides/client`） |
| `/<name>/eve/v1/*` | — | workspace 多 Agent 成员的路由前缀 |

**示例**:

```bash
curl http://localhost:3000/eve/v1/health
```

反向代理（自托管）必须**同时转发 `/eve/` 与 `/.well-known/workflow/` 两个前缀**。

### 4.2 前端集成

框架适配器：`eve/next`（`withEve()`）、`eve/nuxt`（模块）、`eve/sveltekit` / `eve/tanstack`（Vite 插件）；UI 钩子 `useEveAgent`（react / svelte / vue）。可运行示例在 `apps/frameworks/framework-{next,nuxt,sveltekit,tanstack}`。

### 4.3 CLI 命令速查

| 命令 | 作用 |
|------|------|
| `eve init [path]` | 创建 / 注入 Agent 项目 |
| `eve dev` | 开发模式（TUI + 热重载） |
| `eve build` | 构建部署产物（Vercel `.vercel/output` 或自托管 `.output/`） |
| `eve start` | 运行构建产物（Node 服务器） |
| `eve deploy` | 部署 |
| `eve link` | 关联 Vercel 项目并拉取环境变量 |
| `eve add <kind>/<name>` | 从 registry 安装集成（频道 / 连接 / 扩展 / instrumentation） |
| `eve set model <id>` | 切换模型 |
| `eve eval` | 运行评测 |
| `eve info` | 调试 Agent 文件发现结果 |
| `eve remote connect --url …` | 连接远端部署的 Agent |

## 5. 部署

两条官方路线（`docs/guides/deployment/`）：

```text
1) Vercel 路线
   eve link → eve build（产出 .vercel/output）
   → 凭据走项目 OIDC（Gateway 模型甚至无需 API Key）
   → eve deploy 或 Next.js build + withEve

2) 自托管路线
   eve build（产出 .output/ Nitro Node 服务器）
   PORT=3000 eve start --host 0.0.0.0
   → 持久化 .eve/.workflow-data（或选 workflow world 包）
   → 沙箱默认在 Docker / microsandbox / just-bash 中自动选择
```

部署前检查清单：替换 `placeholderAuth()` 为生产路由策略；配置模型凭据；`GET /eve/v1/health` 验证通过。

## 7. 常见问题

### Q: 本地跑不起来 / 需要翻墙登录吗？
A: 本地开发不需要任何浏览器登录：TUI `/login` 支持 ChatGPT 订阅 OAuth、Vercel 账号或直接填 API Key。`chatgpt()` 订阅凭据**只能本地用**，部署时请换成 API Key 或 Gateway。

### Q: cron 定时任务在本地不触发？
A: 设计如此——`eve dev` 永不触发 schedules，`eve start`（或部署后）才会。

### Q: 如何让模型使用本地 Ollama / vLLM？
A: 安装 `@ai-sdk/openai-compatible` 之类的 AI SDK provider 包，把其 LanguageModel 传给 `defineAgent({ model })`，并设置 `modelContextWindowTokens`。

### Q: eval 需要真实 API Key 吗？
A: 不一定。`mockModel` fixture 提供零凭据的确定性运行；真实模型评测（如 e2e 的 `e2e-local` 套件）才需要对应 provider 凭据。

### Q: 想给 Agent 加新的外部服务？
A: 优先 `eve add connection/<name>` 从 registry 安装官方评审过的集成；没有再手写 `defineMcpClientConnection` / `defineOpenAPIConnection`。
